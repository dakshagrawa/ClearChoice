# ClearChoice private-beta mock-only human QA protocol

This protocol targets `0.4.0-beta.1`. **Task16B final wiring is implemented and independently approved; no human QA has been performed.** Automated test callbacks are not human evidence. Site consent, denial, isolation, automatic identical/repeat/reload/SPA lifecycle, revoke, human reenable/new-dialog self-attestation and Chrome Settings site-access removal, history-delete Cancel/confirmation, bounded history/subscription CRUD, retention selection, mock cancellation-help negative boundary and true same-profile restart checkpoints are implemented but human-unverified. Final attestation is offered only after every required checkpoint and the explicitly labeled mixed-evidence stages pass; a final candidate identity recheck precedes stdout-only emission.

## Safety boundary

- Use only the disposable Chromium profile and mock pages supplied by `npm run manual:active-tab-qa`. Never use your personal profile, real checkout, purchase, payment, cancellation or account page.
- The runner extracts the existing exact candidate ZIP using `prepareCandidateArchive`; it must not build or replace the archive after QA. Dirty tracked source fails closed.
- Fixtures contain no forms, account inputs or payment controls. HTTPS `checkout-a.test` and `checkout-b.test` resolve only to the runner's ephemeral `127.0.0.1` listener. A dead proxy bypasses only those two names, all other DNS names are unmapped and QUIC is disabled. A one-day scratch certificate is trusted only through its SPKI pin in this Chromium process. This does not constrain other browsers.
- Read-only observations retain only SHA-256 host-integrity digests and pass/fail predicates. Do not collect raw DOM, values, selectors, URLs or screenshots in markers or feedback. Fixture navigation addresses shown to the operator are not marker data.
- Every main-profile consent, toolbar, CRUD, keyboard and revocation gesture belongs to the human. The runner must not click controls, send keys or seed permissions to imitate consent. The separate synthetic-evidence profile may programmatically open its native action popup and reveal help controls; these actions are labeled programmatic evidence, never human consent.

## Automatic local diagnostics (not evidence)

The human runner writes only allowlisted structured diagnostics to `~/ClearChoice_QA` (Linux default `/home/daksh/ClearChoice_QA`), outside the repository and candidate artifacts. `CLEARCHOICE_QA_LOG_DIR` may select a private, owned directory outside the repository; there is no arbitrary export-file or payload option. Unsafe/symlink directories disable logging with a fixed warning, without weakening the human gate.

Each unique run has append-only `events.jsonl`, atomic `summary.json`, and, when relevant, `issue.json` / `failure.json`. Atomic root `latest.json` exposes `schemaVersion`, `runId`, deduplicatable `eventId`, fixed `event`, `stageId`, `status`, and `needsAttention`; successful preparation adds the unchanged commit/manifest/archive hash binding. Issues remain sticky in `latest.json` while ordinary observations continue in JSONL. A new run resets that pointer; terminal `run_failed`, `run_cancelled`, or `run_completed` publishes the outcome. An external event-driven watcher can read that pointer; the runner sends nothing over a network and changes no Hermes configuration. Events are capped at 2,000 per run, reserving room for an issue and terminal outcome; the summary retains the last 128 events and a dropped-event count. The logger never automatically deletes prior run directories or their contents: matching names, ownership and private modes are not proof that existing files belong to it. Total storage across runs is not capped; operators must review and manage old diagnostics themselves.

A non-overlapping read-only sampler checks only controlled A/B mock pages at most once per second, without attaching native popup CDP sessions, clicking controls, patching DOM, answering dialogs or typing acknowledgements. Diagnostics are fixed booleans, counts, geometry, A/B aliases, route enums and integrity predicates—not raw URLs, text, inputs, IDs, selectors, storage records, stacks or arbitrary instructions. At SPA exit/return checkpoints, an observed route transition establishes that the requested action occurred. A panel/badge mismatch persisting for three seconds then emits an automatic issue even while the runner is waiting, without requiring a screenshot, acknowledgement or forced runner failure. Waiting without an observed transition is not itself an issue. Counts and issues are advisory, not production telemetry or independently sufficient acceptance predicates.

No diagnostic outcome means human QA passed. Consent, denial correlation, separate human acknowledgements, exact-artifact rechecks and schema-6 stdout-only attestation requirements remain unchanged. A setup failure may lack artifact binding; it cannot claim to describe a successfully reviewed candidate. Ctrl+C records cancellation, not a completed QA claim. Tests may synthesize failures/panels solely to verify this logging path; they do not establish production behavior or human evidence.

## Implemented baseline

1. Human toolbar Analyze on clean zero: acknowledge the completed action, read back quiet panel/storage state and check host integrity. Do **not** wait for an empty findings panel to attach.
2. Human Analyze on the positive dynamic mock, Escape, Restore, reanalyze, Dismiss, Restore, repeated Analyze and mock summary replacement; panel transitions and integrity checks gate progress.
3. On clean A, human toolbar → Enable detection for this site → **ALLOW** the genuine native permission prompt. Read back exact browser permission, enabled generation, matching isolated persistent `content.js` registration and unchanged history/subscriptions; clean page/panel/badge remain quiet.
4. Runner navigates A to the form-free recurring fixture. Without Analyze or Save, require a changed accepted history snapshot, recurring item, badge `1` and one automatic panel, then human `DONE`. This does not create a confirmed subscription.
5. First visit to distinct **checkout-b.test** remains unopted and quiet through a bounded observation interval. Human-open the toolbar popup, but wait for the numbered B DENIAL instruction before clicking Enable. The runner installs a request-only witness, verifies the exact B origin/tab and genuine popup identity, then detaches its popup-target observer **before** the permission request. Human Enable → **DENY** the genuine native prompt → explicit `DENIED`. The popup may disappear; no Access denied text or popup false-result callback is required. A fresh trusted Enable click and actual synchronous invocation of the unchanged Chrome permission API must be correlated to this checkpoint, plus unchanged complete storage/permission/script snapshots, no B permission/grant/history/panel and blank badge before and after acknowledgement. Missing permission alone is not proof of denial. This is **humanReportedDenial**, not **browserObserved** Deny.
6. Return to A, observe automatic detection, capture history/subscription digests, then human toolbar → Disable. Require permission/script removal, disabled next generation, blank badge, removed panel and preserved records. Human mock-summary replacement and another mock navigation must remain quiet with no new history.
7. After revoke, human-open the popup and **Refresh history**. The runner binds the first unreviewed A recurring-charge row in production display order from the actual validated snapshot. **Mark reviewed** must change only that row's status; subscriptions remain empty. If all usable rows were already reviewed or subscriptions exist, abort honestly: do not manufacture an initial state or write a hidden reset. Reset only through human UI and rerun the mock workflow.
8. On the same row, **Review as subscription** must open **Confirm observation as subscription** with Merchant, Amount, Currency and Cadence blank. **Cancel** must close the editor with `Editor closed; no additional save requested.` and unchanged storage. Reopen and check the blank draft again.
9. Human-fill fake literals only: Merchant `QA Finding Mock`, Amount `12.34`, Currency `USD`, Cadence `monthly`; leave optional fields blank, then **Save subscription**. Observe `Subscription saved locally.` and read back exactly one persisted subscription linked to the selected `sourceFindingId`.
10. Human **Add subscription**: Merchant `QA Manual Mock`, Amount `23.45`, Currency `USD`, Cadence `yearly`, optional fields blank, then **Save subscription**. Human **Edit** that manual record only: Merchant `QA Manual Mock Edited`, Amount `34.56`, Cadence `weekly`, keep USD, optional fields blank, then Save. Readback requires the same ID/created timestamp and absent manual provenance; the finding-confirmed record remains exact.
11. Human **Delete** the manual record only, observe the correct **Delete confirmation**, then **Cancel**: both records must remain unchanged. Reopen Delete, then **Delete subscription**: observe `Subscription deleted locally.` and require only the manual target removed, with the finding-confirmed record and history preserved. Deletion is local-only and does not cancel billing.
12. Human-select **7 days** in **Keep local observations**. Require validated persisted policy readback, unchanged fresh retained history and unchanged confirmed subscription before DONE. This is policy selection, not proof of elapsed expiry: the main human profile neither ages records nor seeds storage nor changes the clock. A separately disclosed disposable profile later receives four fake observations, including one 40-day-old timestamp, and four fake linked subscriptions; selecting 7 days proves synthetic pruning and subscription preservation, not elapsed real time.
13. Human-click **Cancellation help** on `QA Finding Mock`. This is a **negative boundary**, not positive fallback acceptance: the actual controlled origin is `https://checkout-a.test:<ephemeral-port>`. The pure production `src/shared/guide-catalog.ts` resolver rejects nonempty ports as `none`; require **No known provider site; check your billing provider**, **no anchor**, and the local-only deletion/billing warning. Preserve the confirmed record's canonical `sourceFindingId` linkage; do not strip its origin port, guess provenance, or change production catalog policy to force a link. The regression bundles the actual pure resolver in memory and tests the runner origin shape; its portless safe-origin control is catalog-only, not a browser origin substitution. No provider navigation or account sign-in is permitted. Passing this negative checkpoint alone cannot mark `cancellationHelp` passed; the approved positive catalog/public-article evidence is described below and is not provider-browser navigation.
14. Explicit human DONE authorizes a real browser close/reopen of the same profile, retaining the same TLS server and certificate. Install happens once through CDP `Extensions.loadUnpacked`; both launches omit `--load-extension` and `--disable-extensions-except` and exclude Playwright's default `--disable-extensions`. Restart only wakes the persisted extension, independently binds its activated worker/runtime identity, then compares schema-validated history/subscription/settings digests, policy, disabled grant generation, absent optional access and absent registrations. No grants are seeded and no scripts are re-registered. Fresh host-integrity baselines bind recreated mock tabs. Human-open the native toolbar popup to confirm retained state again.
15. Following restart, the runner checks final main-profile state and human keyboard/visual acknowledgements, then performs the separately labeled synthetic expiry and packaged-catalog review below. Only complete explicit results permit **ATTEST**. Human stages require observations followed by separate acknowledgements; waits are bounded. If no genuine Chrome permission prompt is available, abort rather than simulate consent or denial.

## Readback prerequisite correction

Site observations validate the entire storage snapshot **before** capturing baselines or comparing permissions. Pure production history, subscription, retention and grant validators are bundled in memory for read-only worker evaluation; the mutating storage loader is never invoked and no extension artifact is rebuilt. Receipts, version boundaries and dismissed settings are checked explicitly. Unsupported versions, incomplete versioned collections, malformed nested records and surplus grant fields abort rather than become empty defaults. Truly pristine missing collections remain supported. Returned observations contain only predicates/counts; retained comparison state contains only digests and numeric identifiers.

The history/subscription slice reuses that exact production validator in every storage observation mode. Worker comparison state contains only SHA-256 digests and phase numbers; popup reads return booleans only. Wrong provenance, extra records, changed history/settings, cancellation mutations, replacement identity and wrong deletion targets cannot pass. Tests use explicitly synthetic snapshots/DOM and establish no human evidence. Incomplete or false stage results prevent ATTEST and marker emission; exact-archive requirements remain unchanged.

## Expanded exact-artifact attestation

Schema **6** requires exactly the fixed commit, packaged-manifest hash, archive hash, `local-human-attestation` reviewer, passed outcome, clean/dynamic integrity, accessibility, and passed `optInConsent`, `optInDenial`, `siteIsolation`, `automaticLifecycle`, `revocation`, `reviewHistory`, `subscriptions`, `retention`, `cancellationHelp`. It additionally requires the literal `optInDenialEvidence` label **`humanReportedDenial-correlated-real-request-and-verified-isolation-not-browserObserved`**, alongside the unchanged retention and cancellation-help mixed-evidence labels above. Missing, false, non-pass, extra, mislabeled callback or old-schema fields fail closed. The constructor requires explicit complete workflow results; it cannot generate PASS from candidate identity alone. Schema 5 and older markers fail closed.

### Approved denial evidence decision and limits

The owner explicitly approved human `DENIED` acknowledgement correlated to the request/site plus verified isolation. Chrome 141 can destroy the native action popup before a pointer Deny response reaches its JavaScript promise; attaching a popup CDP session across that modal can pin its lifetime and misrepresent ordinary behavior. The runner therefore never waits for a destroyed popup's callback, opens a replacement to manufacture status, or answers a prompt. A transparent runner-only wrapper calls the original `chrome.permissions.request` synchronously on the trusted click stack, returns its exact result unchanged, and only after invocation sends a fixed request witness to a temporary in-memory listener in the reviewed worker. It never observes or transforms that promise's result. No production bytes, grant records, storage, clock, or permission state are changed by the witness.

The fresh random checkpoint nonce, exact reviewed popup sender, B origin and baseline tab ID bind one trusted request. Requests made before observer detachment, duplicates, wrong sites/tabs/senders, untrusted/no actions, tab activation/navigation and stale evidence fail closed. Complete canonical storage, permissions and script snapshots are hashed transiently and rechecked; records, receipts, settings or unrelated grants cannot change unnoticed. The receiver is removed at checkpoint completion/failure; worker loss or unavailable witness times out rather than passing. Preparation, request observation and terminal acknowledgement are bounded, with request freshness capped at five minutes from arming. Correlation state never appears in the data-free marker. The human reports having chosen actual Deny; the runner independently proves request invocation and safe isolation, **not a browser-observed Deny callback or independently observed native response**. A dismissed prompt cannot honestly receive `DENIED`; if no genuine prompt appears, abort. This revised contract does not retrospectively pass any prior run and no current human QA pass is claimed.

The marker is JSON on stdout only, never written to a caller path by the runner. Save only a genuine completed human attestation outside the repository, then supply `CLEARCHOICE_ACTIVE_TAB_QA_MARKER` to `npm run check:beta`. Until a human completes every mandatory stage, the gate remains closed. Do not forge a marker or treat unit fixtures as a real attestation.
