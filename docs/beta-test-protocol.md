# ClearChoice private-beta test protocol

Use this protocol for the `0.3.0-beta.1` private opt-in beta. Testing is voluntary. There is no feedback collection by the extension.

## Before testing

1. Use your **own Chromium profile** and an **independently selected page**. Do not use a page selected, supplied, or navigated by ClearChoice.
2. Test only an English consumer checkout-like page that you may safely view without signing in or entering information.
3. Do not make purchases, do not submit or enter payment information for ClearChoice, and do not enter account, address, card, order, receipt, or other personal data for this test.
4. Stop immediately on restricted/unsupported pages, pages requiring login, payment entry, submission, or any page you are not authorized to inspect. Do not try to bypass restrictions.

## Test steps

1. Open the selected page in your own Chromium profile.
2. Open ClearChoice and click **Analyze this tab** yourself.
3. If ClearChoice reports the page is restricted or unsupported, stop and record only that outcome in sanitized feedback if you choose to send it.
4. For each notice, compare the notice against the visible text on the page. Do not treat a notice as a legal, compliance, safety, or deceptive-site conclusion.
5. Do not click checkout, purchase, payment, account, cancellation, refund, or submission controls for ClearChoice testing.

## Optional feedback

Feedback is voluntary and external to the extension. If you choose to send it, use [the feedback template](beta-feedback-template.md). Send only the rule, expected result, actual result, and browser version. Do not send URLs, screenshots, personal data, addresses, card data, order data, receipts, or page content.

For the separate repository gate, `npm run check:beta` needs a real external human activeTab marker generated by the documented manual fixture runner. Never create or forge a marker. If no marker exists, the expected result is a closed failure due only to its absence.
