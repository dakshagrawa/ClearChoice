# ClearChoice 0.3.0-beta.1 private-beta release checklist

> This checklist tracks work required for the production-ready **private opt-in beta** target `0.3.0-beta.1`; it does not claim the beta is release-ready. All criteria below remain unchecked, so readiness is pending required checklist and gate completion, including the deliberate human activeTab QA marker and a passing `npm run check:beta`. It is not a Chrome Web Store release checklist; policy review and submission are future separate work, not complete. For v0.2.0 mock-only historical evidence, see [release-checklist.md](release-checklist.md).

- [ ] The beta manifest has exactly ordered `activeTab`, `scripting`, and `storage`; `host_permissions` is `[]`; it declares exactly `_execute_action` with suggested `Ctrl+Shift+Y`, and no optional permissions, static content scripts, background service worker, external connection declaration, or remote executable code.
- [ ] The popup can analyze only the active current tab after a deliberate button press. It injects no code on popup load, never searches or messages non-active tabs, and reports restricted/unsupported pages without crashing.
- [ ] The content script cannot register duplicate listeners or panels after repeated Analyze presses or SPA rerenders. It analyzes only visible non-form-field text and checked paid controls; it excludes typed input, textarea, select, password, payment, and contenteditable values, and discards whole static context/finding candidates that contain sensitive-looking email, payment-card/PAN/masked-card, account/bank/routing-number, CVV, or security-code text.
- [ ] Page analysis stays page-local: popup responses contain only a status and integer count. No URL, title, evidence, selector, DOM text, timestamps, page HTML, form value, payment data, or finding is stored or sent outside the content-script context.
- [ ] The beta supports English checkout-like contexts only. It recognizes a conservative checkout context before showing notices; otherwise it says that the page does not look like a supported checkout context. It retains existing recurring/add-on evidence rules and "possible" language.
- [ ] Every interactive surface works with keyboard and pointer input. The packaged-popup accessibility Playwright test loads actual `dist`, runs Axe serious/critical checks, and verifies Tab reaches Analyze then Restore. Separately, the browser payload-level Playwright test injects only the source content payload with a minimal fake extension bridge in light/dark fixture contexts, measures real 44px Dismiss bounds, uses actual Tab navigation to reach Dismiss, and verifies Escape ownership. It is not packaged MV3, popup, or `activeTab` coverage.
- [ ] Automated content-payload/JSDOM integration tests retain URL, form, control, and host-node integrity snapshots for Analyze, Dismiss, Restore, repeated Analyze, and dynamic replacement. They do not claim packaged MV3, popup, `activeTab`, or production injection validation. Automated packaged Playwright proves direct-popup denial (no false activeTab grant) and packaged-popup accessibility only. Successful actual active-tab panel accessibility is human attested.
- [ ] `npm run check:beta` is a Linux Chromium private-beta gate and passes from a clean checkout only on Linux with a deliberately saved local manual active-tab QA marker whose actual opened target resolves outside the repository for the exact commit and manifest. It must fail closed before opening a marker on macOS or Windows with an explicit diagnostic that descriptor binding requires Linux `/proc/self/fd`; no portability support is claimed. On Linux, unit tests, lint, beta build, static package scan, ZIP integrity, and marker validation run automatically. The documented runner never writes a marker: a human first runs clean and dynamic fake fixtures in visible Chromium, uses pointer toolbar-click/popup-Analyze for each, visibly verifies on the actual panel that Tab focus reaches Dismiss and Escape closes only that panel, and completes the dynamic Dismiss, Restore, repeated Analyze, and replacement sequence. It transiently computes an in-page canonical integrity representation and transiently reads controlled fake-fixture data only to derive a SHA-256 digest. Its retained QA state contains only that digest and boolean pass/fail predicates, and its output contains only predicate/attestation fields; neither retains a URL, title, DOM text/HTML, form/control value, node reference, name/type, selector, evidence, or finding. After literal terminal `ATTEST`, it emits a data-free JSON self-attestation with exactly schema version 2, pass outcome, `cleanFixtureIntegrity: "passed"`, `dynamicFixtureIntegrity: "passed"`, `accessibility: true`, commit, manifest hash, and the fixed reviewer token. `check:beta` opens the terminal path component without following it, validates the opened descriptor is regular, then resolves/checks that opened descriptor target outside the repository before parsing; a post-open parent-symlink swap must still read the originally opened external marker rather than resolve or reopen by pathname. Parent-directory symlinks are allowed only when their actual opened target resolves outside the repository; this does not promise to reject every ancestor symlink. No automated E2E success claim substitutes for it. No tag, publication, upload, or push is part of this private-beta gate.
- [ ] Documentation accurately says **private opt-in beta**, explains temporary `activeTab` access and no persistent host access, confirms all page data stays local with no telemetry, accounts, or uploads, lists unsupported cases, and gives a manual tester protocol. The beta is advisory-only. No store listing, upload, push, or publication occurs.

## Tester and data commitments

- [ ] The beta supports English consumer checkout contexts only and is advisory only; it makes no deceptive-site, legal, compliance, safety, or consumer-protection conclusion. False positives and false negatives are documented.
- [ ] All page data remains local: there is no telemetry, accounts, or uploads. Typed editable values are excluded; sensitive-looking static candidates are discarded whole rather than redacted or retained.
- [ ] The extension does not automate purchases, payments, accounts, cancellations, refunds, subscriptions, or checkout submission.
- [ ] Manual testers use [the beta test protocol](beta-test-protocol.md) and [feedback template](beta-feedback-template.md). Feedback is voluntary, external, sanitized, and not collected by the extension.
- [ ] Contributors use Node 22.12+; current verified Node is 22.23.2. `check:beta` may pass only with a real external human activeTab marker for the exact commit and manifest. Do not create or forge a marker; without it, the gate must fail closed.
