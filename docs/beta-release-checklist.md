# ClearChoice 0.3.0-beta.1 private-beta release checklist

> This checklist defines future beta acceptance gates. It does not indicate that the beta has been implemented or released. For the v0.2.0 mock-only historical evidence, see [release-checklist.md](release-checklist.md).

- [ ] The beta manifest has exactly ordered `activeTab`, `scripting`, and `storage`; `host_permissions` is `[]`; it declares exactly `_execute_action` with suggested `Ctrl+Shift+Y`, and no optional permissions, static content scripts, background service worker, external connection declaration, or remote executable code.
- [ ] The popup can analyze only the active current tab after a deliberate button press. It injects no code on popup load, never searches or messages non-active tabs, and reports restricted/unsupported pages without crashing.
- [ ] The content script cannot register duplicate listeners or panels after repeated Analyze presses or SPA rerenders. It analyzes only visible non-form-field text and checked paid controls; it never reads typed input, textarea, select, password, payment, or contenteditable values.
- [ ] Page analysis stays page-local: popup responses contain only a status and integer count. No URL, title, evidence, selector, DOM text, timestamps, page HTML, form value, payment data, or finding is stored or sent outside the content-script context.
- [ ] The beta supports English checkout-like contexts only. It recognizes a conservative checkout context before showing notices; otherwise it says that the page does not look like a supported checkout context. It retains existing recurring/add-on evidence rules and "possible" language.
- [ ] Every interactive surface works with keyboard and pointer input; automated accessibility checks pass for the popup and panel in both light and dark fixture contexts; the existing 44px dismissal target and Escape behavior remain intact.
- [ ] Automated content-payload/JSDOM integration tests retain URL, form, control, and host-node integrity snapshots for Analyze, Dismiss, Restore, repeated Analyze, and dynamic replacement. They do not claim packaged MV3, popup, `activeTab`, or production injection validation. Automated packaged Playwright proves only direct-popup denial (no false activeTab grant).
- [ ] `npm run check:beta` is a Linux Chromium private-beta gate and passes from a clean checkout only on Linux with a deliberately saved local manual active-tab QA marker whose actual opened target resolves outside the repository for the exact commit and manifest. It must fail closed before opening a marker on macOS or Windows with an explicit diagnostic that descriptor binding requires Linux `/proc/self/fd`; no portability support is claimed. On Linux, unit tests, lint, beta build, static package scan, ZIP integrity, and marker validation run automatically. The documented runner never writes a marker: a human first runs clean and dynamic fake fixtures in visible Chromium, uses pointer toolbar-click/popup-Analyze for each, and completes the dynamic Dismiss, Restore, repeated Analyze, and replacement sequence. It retains only pass/fail integrity predicates. After literal terminal `ATTEST`, it emits a data-free JSON self-attestation with exactly schema version 2, pass outcome, `cleanFixtureIntegrity: "passed"`, `dynamicFixtureIntegrity: "passed"`, commit, manifest hash, and the fixed reviewer token. `check:beta` opens the terminal path component without following it, validates the opened descriptor is regular, then resolves/checks that opened descriptor target outside the repository before parsing; a post-open parent-symlink swap must still read the originally opened external marker rather than resolve or reopen by pathname. Parent-directory symlinks are allowed only when their actual opened target resolves outside the repository; this does not promise to reject every ancestor symlink. No automated E2E success claim substitutes for it. No tag, publication, upload, or push is part of this private-beta gate.
- [ ] Documentation accurately says **private opt-in beta**, explains temporary active-tab access/local processing, lists unsupported cases, and gives a manual tester protocol. No store listing, upload, push, or publication occurs.
