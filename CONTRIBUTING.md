# Contributing to ClearChoice

Issues and pull requests are welcome. This is a proprietary, source-available
project, not an open-source project. Read [LICENSE](LICENSE) before copying,
modifying, testing, or contributing code.

## Ownership and permission

You retain copyright in your original contributions. Submitting an issue or PR
is not an assignment of your copyright, permission to merge, or a transfer of
repository access.

Before code is merged, explicitly confirm in the PR that you have the necessary
rights and grant Daksh Agrawal a nonexclusive, worldwide, perpetual,
royalty-free permission to use, modify, reproduce, distribute, and sublicense
your contribution as part of ClearChoice under its proprietary license. Do not
submit code subject to incompatible terms. Identify third-party material and
preserve its license and attribution. The maintainer must obtain this explicit
permission rather than infer it merely from a submitted PR.

If you do not want to grant that permission, you may still open an issue or
suggest an approach without contributing code. Do not submit secrets, account
information, payment data, or other people's private information.

## Review and safety

- Work in a feature branch or a fork. Do not push directly to protected branches.
- Keep changes focused and describe the problem, solution, tests, and risks.
- Use only fake data and controlled mock fixtures for testing.
- Follow the project's existing test and package checks. Passing checks do not
  authorize a release or establish human acceptance.
- Resolve review conversations before merging. Only authorized maintainers may
  merge; opening a PR does not grant write access.
- Changes to licensing, permissions, workflows, security policy, or releases
  require particular care and explicit maintainer review.

For sensitive security reports, use GitHub's private vulnerability-reporting
feature when available; otherwise contact the maintainer privately. Do not
post exploitable secrets or private records in public issues.
